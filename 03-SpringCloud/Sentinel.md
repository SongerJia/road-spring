## 熔断降级
为什么要熔断->雪崩效应->熔断原理->状态机->降级->限流->Sentinel核心->面试高频题
### 为什么要熔断
什么是雪崩效应
```
// 服务调用链：A → B → C
// ① C 挂了/变慢 → B 调用 C 一直等待（占用线程）
// ② B 的线程被占满 → B 也挂了
// ③ A 调用 B 也超时 → A 也挂了
// → 整个链路崩溃（雪崩）

// 核心：下游故障通过"等待/重试"向上游传导
```
解决思路
```
// ① 超时控制：调用设超时，不让线程无限等
// ② 重试控制：避免雪上加霜
// ③ 熔断：连续失败就"短路"，不再调用
// ④ 降级：失败时返回兜底（不抛错）
// ⑤ 限流：保护自己不被打垮
```
### 熔断原理
熔断 Circuit Breaker：类似电路保险丝。连续失败达到阈值，熔断器断开，一段时间内不再调用下游，直接走降级。过段时间半开试探，恢复正常则闭合。
三种状态
```
闭合（CLOSED）───────── 连续失败超阈值 ─────────→ 打开（OPEN）
   ↑                                                  │
   │                                             冷却时间到
   │                                                  │
   └────────── 调用成功，恢复 ──────── 半开（HALF-OPEN）←─┘
                                   （放少量请求试探）
```

|状态|行为|何时进入|
|---|---|---|
|**CLOSED（闭合）**|正常调用|初始/恢复|
|**OPEN（打开）**|直接拒绝（走降级）|失败率超阈值|
|**HALF-OPEN（半开）**|放少量请求试探|冷却时间到|
熔断触发条件
```
// ① 失败率阈值：如 50% 请求失败
// ② 最小请求数：如至少 5 个请求才统计（避免偶然）
// ③ 熔断时长：打开后持续多久（冷却期）

// 参数示例：
// 最近 10 秒内，失败率 >= 60%，且请求数 >= 5 → 熔断 10 秒
```
半开试探
```
// 冷却时间到 → HALF-OPEN
// 放 1 个（或几个）请求试探下游
// 成功 → 恢复 CLOSED
// 失败 → 重新 OPEN
// 防止"下游恢复了但还在熔断"和"下游没好就全量放行"
```
### 降级 Fallback
降级是什么
```
// 熔断/超时/异常时，返回"兜底结果"而不是抛错
// 保证用户体验（返回旧数据/默认值/提示）

// 降级 vs 熔断：
// 熔断：机制（短路不调用）
// 降级：结果（返回兜底）
// 熔断后的处理方式就是降级
```
降级方式
```
// ① 返回默认值
public Result getStock(Long id) {
    try {
        return stockClient.getStock(id);
    } catch (Exception e) {
        return Result.fail("服务繁忙，请稍后重试");  // 降级
    }
}

// ② 返回旧缓存数据（脏数据兜底）
// ③ 异步消息降级（记录后补处理）
// ④ 返回静态/简化响应
```
降级场景
```
// ① 下游熔断/超时
// ② 大促流量高峰（非核心功能降级）
// ③ 依赖服务升级/维护
// ④ 资源不足（线程池满）
```
### 限流
限流是什么
```
// 控制进入的请求速率，防止服务被打垮
// 两种思路：
// ① 保护下游：熔断降级
// ② 保护自己：限流

// 常见算法：
// ① 固定窗口：每秒最多 N 个
// ② 滑动窗口：更平滑
// ③ 令牌桶：允许突发（Nginx 用）
// ④ 漏桶：恒定速率
```
Sentinel限流
```
@SentinelResource("getOrder")  // 定义资源
public Order getOrder(Long id) {
    return orderService.getById(id);
}

// 控制台配置：QPS 阈值、线程数阈值
// 超过阈值 → 拒绝/排队
```
限流+熔断+降级组合
```
请求进入
    ↓
① 限流（Sentinel）：超过 QPS → 拒绝
    ↓
② 调用下游（Feign）
    ↓
③ 超时/失败 → 熔断器统计
    ↓
④ 熔断打开 → 走降级（fallback）
```
### Sentinel核心
Sentinel是什么
```
// 阿里开源的流量防护组件
// 三大能力：
// ① 流量控制（限流）
// ② 熔断降级
// ③ 系统负载保护

// 对比 Hystrix：
// Hystrix 已停止开发
// Sentinel 功能更强（限流+熔断+实时监控+控制台）
// 推荐：Sentinel
```
核心概念
```
// ① 资源（Resource）：被保护的代码（方法、URL）
// ② 规则（Rule）：限流/熔断的规则
// ③ 控制台（Dashboard）：可视化配置监控
// ④ 客户端（Sentinel SDK）：嵌入应用
```
常见注解
```
@SentinelResource(
    value = "getOrder",              // 资源名
    blockHandler = "getOrderBlock",  // 限流降级方法
    fallback = "getOrderFallback"    // 异常降级方法
)
public Order getOrder(Long id) {
    return orderService.getById(id);
}

// blockHandler：限流/熔断触发
public Order getOrderBlock(Long id, BlockException ex) {
    return new Order();  // 限流兜底
}

// fallback：业务异常触发
public Order getOrderFallback(Long id, Throwable t) {
    return new Order();  // 异常兜底
}
```

|规则|作用|
|---|---|
|**流控规则**|QPS/线程数限流|
|**熔断规则**|慢调用/异常比例/异常数|
|**热点规则**|参数维度限流|
|**授权规则**|黑白名单|
|**系统规则**|系统负载保护|
